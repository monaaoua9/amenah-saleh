# Architecture

```
 producers (gRPC bidi stream, JSON codec)
      |  Batch{producer, events[seq,key,time,value]}
      v
 +-----------+   credits (MaxInflight events, semaphore)
 |  ingest   |<--------------------------------------------+
 +-----+-----+                                             |
       | hash(producer) -> lane                            |
       v                                                   |
 +--------+  +--------+                                    |
 | lane 0 |  | lane 1 |   seq dedup, partition, barrier    |
 +---+----+  +----+---+   fan-out, punctuation fan-out     |
     |  \      /  |                                        |
     |   \    /   |       Hash(key) or RoundRobin          |
     v    v  v    v                                        |
 +------+ +------+ +------+ +------+                       |
 | w0   | | w1   | | w2   | | w3   |  window operator,     |
 +--+---+ +--+---+ +--+---+ +--+---+  watermark, state     |
    \        |        |       /        (credits released   |
     \       |        |      /          after sink accepts)-+
      v      v        v     v
          +---------------+
          |     sink      |  stages output per checkpoint epoch,
          +---------------+  emits only after the checkpoint is durable

 coordinator: Begin(id) -> barrier into every lane -> acks from
 lanes + workers + sink -> _COMPLETE marker -> sink.commit(id)
```

## Pieces

**Ingest / partitioning** (`internal/ingest`, `internal/partition`).
A producer stream is pinned to one lane by hashing its name, so per-producer
order holds and `Seq` dedup is a single map lookup. Lanes route each event to a
worker with `Hash` (FNV-1a, keyed state stays on one worker) or `RoundRobin`
(stateless stages only; it splits keyed windows).

**Event time** (`internal/window`). Tumbling, sliding or session (`Gap`) windows on event time. Sessions merge when an event bridges two of them and fire once the watermark passes last-event + gap; they have no allowed lateness. The
watermark is `max(event time) - Disorder`. A window fires when the watermark
passes its end, stays around for `Lateness` ms and re-fires (`Late: true`) if
stragglers land in it, and anything older than that is counted and dropped.
`AdvanceWatermark` injects a punctuation for idle keys / end of input; workers
apply the minimum across lanes so a quiet lane can't push time past data still
queued on a busy one.

**Backpressure** (`internal/engine`). Two layers. Every channel is bounded, and
on top of that an event-count semaphore caps total in-flight events across the
whole pipeline, which is what actually bounds memory. Credits come back only
after the worker has handed its output to the sink, so a slow sink slows
ingest. `Submit` blocks (the gRPC handler stops reading, HTTP/2 flow control
stalls the client); `TrySubmit` / `-shed` returns `RESOURCE_EXHAUSTED`.

**Checkpoints** (`internal/checkpoint`, `internal/engine/align.go`).
Chandy-Lamport style marker snapshot, in the aligned-barrier form used by
Flink. The coordinator injects a numbered barrier into each lane. Each task
snapshots when it has seen the barrier from *every* upstream, holding back
records from upstreams whose barrier already arrived, so channel state is empty
by construction and nothing needs recording. Snapshots are written
tmp + fsync + rename; a checkpoint only exists once `_COMPLETE` is written.
Last 3 are kept. If staged sink output passes `MaxPending` the sink asks for an
early checkpoint, which keeps its memory tied to output volume instead of the
checkpoint interval (a soft limit: results already in flight still land). Profile a running server with `-pprof :6060`.

**Rescaling.** Keys map to one of 128 key groups and a worker owns a range
of them. A checkpoint records the lane/worker counts; on restore each new
worker loads every old worker snapshot and keeps the keys it now owns, and
each producer's last `Seq` moves to the lane its hash selects. Requires a
keyed partitioner (`Hash`); round-robin refuses.

**Producer contract.** Every `Ack` carries `committed_seq`, the highest `Seq`
of that producer inside a completed checkpoint. `ingest.Producer` numbers
events, keeps batches above `committed_seq`, and on a broken stream reconnects
and resends them; the lane's `Seq` dedup drops what the engine already has.

**Exactly-once.** State is restored from the last complete checkpoint, the
producer replays from any point at or before it, and lanes drop `Seq <= last`
per producer. Sink output of an uncommitted epoch is discarded on crash and
regenerated by replay. `TestExactlyOnceAcrossCrash` checks the result is
identical to a run with no crash.

## Cluster mode

```
 producers --gRPC--> master: ingest, lanes, sink, coordinator, checkpoint store
                       |  ^
          Data/Barrier/|  |Results/SinkBarrier/Snap/Done   (one bidi stream per node)
          Punct/Init   v  |
                    worker node 0..N-1: aligner + window operator
```

Lanes still write `workerMsg` into a per-worker channel; for a remote worker a
proxy drains that channel onto the wire, so nothing upstream changes. The node
runs the very same `worker` code behind a different `workerEnv` (stream instead
of in-process calls). Replies are ordered on the stream: results, then the
forwarded barrier, so the sink's alignment still holds. Credits come back with
`Done`, so remote backpressure is the same mechanism.

Nodes carry no durable state. `Init` tells a node which worker it is and, on
restore, hands it its snapshot (or every snapshot plus its key groups when the
worker count changed). A lost stream cancels the engine; the supervisor in
`cmd/engine` stops it, waits for the nodes to be back, and starts a new one
that restores from the last checkpoint.

## Around the engine

Everything below sits outside the exactly-once core and is wired in
`cmd/engine`.

- **Ingest side** (`internal/ingest`, `internal/filter`): the rate limiter and the
  filter run after a batch is read and before it is submitted. A filtered event
  still counts as received in the ack (`LastSeq` is taken before filtering),
  otherwise the producer would keep it in its replay buffer forever. The filter
  is deterministic, so replays drop the same events.
- **Quantiles** (`internal/sketch`): a log-bucket sketch per window with 2%
  relative error. It merges, which is what session bridging needs, and it is
  gob-encoded inside the window snapshot, so it is checkpointed and rescaled
  like the other aggregates. Off by default; the per-event cost is a `log`.
- **Timers** (`internal/window/timers.go`): `Advance` pops due windows off a min-heap
  of end times (and, for sessions, one entry per key) instead of scanning all
  open state. With 200k open windows a no-op `Advance` went from ~12 ms to
  ~20 ns. The heaps are derived state, rebuilt after every restore, so snapshots
  are unchanged. `timers_test.go` runs the heap against the old full scan on
  random out-of-order input.
- **Distinct count** (`internal/hll`): 1 KiB of registers per open window, merged
  by register max, so sessions and snapshots treat it like the quantile sketch.
  It counts distinct *values* (window state is already per key). Off by default.
- **Outputs** (`internal/output`): sinks hang off `OnResult`, so they only see
  results after the checkpoint is durable. The webhook retries 5xx; receivers
  dedup on (key, start) because of the at-least-once case below. The late-event
  side output is called from the worker goroutines and is at-least-once, replay
  after a crash can report the same event again.
- **Alerts** (`internal/alert`): evaluated on emitted results. Cooldown is in
  event time (the result's end), so a replay of the same file alerts the same
  way as the live run.
- **Checkpoint compression**: `Put` writes `task.snap.gz`, `Get` tries `.snap`
  first and then `.snap.gz`, so flipping `-ckgzip` between restarts is safe.

## Known gaps

- Sink output is staged inside the checkpoint and re-sent on restore if the
  `_EMITTED` marker is missing, so a crash never loses an epoch. A crash
  between the emit and the marker re-sends it: at-least-once for that one
  epoch, downstream dedups on (key, window start).
- After a rescale the watermark restarts at the slowest old worker's, so a very
  late event can be accepted that an unscaled run would have dropped.
- Cluster recovery is a full rollback; a surviving worker is restored too.
- Exactly-once needs a producer that follows the protocol: contiguous `Seq`, and
  replay of everything above the ack's `committed_seq`. `ingest.Producer` does
  this; a hand-rolled client has to. The engine keeps no source offsets beyond
  the per-producer last `Seq`.
